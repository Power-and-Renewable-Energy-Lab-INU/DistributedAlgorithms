# Distributed Algorithms

This repository contains the resources associated with our research on distributed algorithms. It includes the complete dataset used throughout the study, encompassing both earlier and updated versions to facilitate reproducibility and comparative analysis. At present, access to we offer limited access to our distributed algorithm through a cloud-based service for public testing and getting results without requiring local deployment. In contrast, the plotting and visualization scripts are fully available within this repository. The full source code of the proposed algorithm will be released in subsequent versions following comprehensive testing, validation, and documentation to ensure reliability, usability, and long-term maintainability.

## Folder Structure

- **assets/**: Contains simulation videos and images.
- **Data-v1/**: Older dataset version.
- **Data-v2/**: New dataset version, used by the local distributed workflow.
- **services/**: Contains the local service entry points for the distributed algorithm [services/distributed.py](services/distributed.py). and the plotting utility in [services/plottings.py](services/plottings.py).
- **results/**: Stores output files generated by the service, organized by bus name. Each run includes operation results and, when plotting is requested, a plots/ folder with the generated figures.

## For Test Running the Distributed Algorithm With Our Default Datasets

The distributed workflow is implemented in [services/distributed.py](services/distributed.py).

### Create and activate a virtual environment

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Install dependencies

```bash
pip install -r requirements.txt
```

### Run a test

```bash
python services/distributed.py --bus 13bus_base --use_chronic chronic_1 --horizon 24
```

Arguments:
- --bus: Selects the bus dataset folder under Data-v2.
- --use_chronic: Selects the chronic scenario folder.
- --horizon: Number of timesteps to simulate (default: 24).

Note: The current workflow is limited to at most 150 agents for resource constraints. Dataset folders with more than 150 agents will be rejected before execution.

The service sends each timestep to the cloud-based endpoint where the algorithm is executed, stores the operation results in the corresponding bus folder under results/, and writes the operation_results.csv file for the selected run. For a custom dataset, create a new folder under Data-v2 with the required files such as bus.csv, demand.csv, dg.csv, res.csv, ess.csv, demandmultiplier.csv, renewablemultiplier.csv, and the corresponding chronic folder(s). Then invoke the service with that folder name using the --bus argument.

### Generate plots from the saved results

The plotting utility in [services/plottings.py](services/plottings.py) creates three figures for a selected bus system:

- operation.png: 24-hour stacked operation plot
- convergence.png: per-interval convergence iteration plot
- topology.png: single-line network topology diagram

Run the plotting workflow for the existing 13-bus base case with:

```bash
python services/plottings.py --bus 13bus_base
```

The script reads the saved operation results from the corresponding `results/<bus_name>/operation_results.csv` file and the topology inputs from the matching `Data-v2/<bus_name>` dataset folder. For all bus systems, topology symbol sizes are loaded from `Data-v2/<bus_name>/plotting_params.json` when present; if that file is missing, the script uses built-in default symbol size values.

Example result structure for the 13-bus case:

```text
results/
└── 13bus_base/
    ├── operation_results.csv
    └── plots/
        ├── operation.png
        ├── convergence.png
        └── topology.png
```
